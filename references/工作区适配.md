# 工作区适配、证据与版本

本文件内置报告运行所需的输出、证据和项目衔接规则。读取项目实际状态与材料作为输入；分析方法只使用本 Skill 包。当前任务中已生效的用户与工作区指令优先，发生具体规则变化时以其为准。

## 1. 决定输出位置

以当前任务工作区或用户明确指定的目标项目为准，不以本 Skill 的安装目录决定输出位置。

### PE 工作台项目

目标项目实际位于 `D:\一级项目尽调\10_项目库\PE-YYYY-NNN_项目简称` 时，使用本节模式。

- 读取 `00_项目控制` 的四份实际记录：`01_项目总览.md`、`02_资料与证据.md`、`03_问题风险与行动.md`、`04_决策与版本.md`。确认用户要求初筛或修订报告及当前授权范围，已明确的授权不再重复询问。
- 材料入口为 `10_机会录入与初筛/01_输入材料`，含 `00_待登记`、`01_已登记原件`、`90_转换与提取`。访谈在同阶段的 `02_初步访谈`，保持扁平。
- 已有材料编号沿用；新增材料按 SHA-256 去重，原件不改写。同名不同哈希保留版本关系，转换件注明原件、提取方法与时间。Wiki 是外部引用，不复制为项目原件。
- 报告输出到 `10_机会录入与初筛/03_阶段成果/初筛报告_v0.1_待复核.md`，已有报告按实际版本续修。
- 过程稿输出到该阶段成果目录的 `90_过程稿/初筛报告_YYYYMMDD-HHMM/`。名称冲突则加序号，保留之前未审核批次；只有真实编制时创建。
- 报告事实和判断先进入已有 `20_立项/02_立项工作底稿` 的适用文件；该目录由初筛与立项共用，不复制全面尽调底稿。

| 主题 | 初筛底稿主维护位置（相对于 `20_立项/02_立项工作底稿`） |
|---|---|
| 主体与交易事实 | `01_项目与交易概况/项目基本信息.md`、`交易背景与融资需求.md` |
| 行业竞争 | `02_行业市场与竞争/行业市场初步判断.md`，按 [竞争格局研究](竞争格局研究.md) 保留覆盖记录、企业及融资案例 |
| 产品与商业模式 | `03_产品技术与商业模式/产品业务初步判断.md` |
| 客户与商业化 | `04_客户经营与商业化/客户与商业化初步判断.md` |
| 团队股权治理 | `05_团队股权与治理/团队股权治理初步判断.md` |
| 财务融资估值 | `06_财务融资与估值/财务融资估值初步判断.md` |
| 风险、假设及缺口 | `07_风险缺口与投资假设` 中的初步风险、投资假设及资料缺口文件 |

项目状态、目录或命名已经调整时沿用该项目实际主维护位置，不新建平行事实库。四份主记录按受影响内容更新：来源与重要 Wiki 引用进资料与证据，未决问题与行动进问题风险与行动，报告版本和用户审核进决策与版本，总览反映当前进展及下一动作；若总览状态发生变化，同步现有工作台 CSV 导航视图。只更新本任务涉及字段，不把研究建议记录成正式阶段决定。

### 其他工作区或未建档材料

遵循当地已经生效的目录约定或用户指定位置；没有约定时，在当前工作区的 `初筛报告/<项目简称>/` 下输出报告，过程稿在其 `90_过程稿/初筛报告_YYYYMMDD-HHMM/`。简称先从材料可靠提取，涉及多个主体且无法确定目标时询问用户。

已有当地底稿时复用；没有时在报告旁保留一份 `分析与来源.md`，只记录支撑报告的事实、计算、来源和关键缺口，不创建 PE 工作台四主记录或阶段目录。当前工作区没有可写本地目录时，先完成可在聊天中审阅的内容，再明确缺少的文件输出条件。

在 PE 工作台收到未正式建档材料时，也可按用户明确要求生成独立初筛报告；用户要求正式建档则需要项目简称、来源、负责人、密级和授权范围，沿用环境已有建档流程。仅调用本 Skill 不自动建档或启用阶段。

## 2. 证据与数字脚注

区分公司披露、管理层陈述、外部独立来源、专业机构意见、计算结果、投资判断及待核实事项。资料未提供的事实保留缺口；没有财务数据时报告相应财务值留空，不填零。

至少保存以下定位：文件名及页码／工作表／章节，访谈日期和对象，网页标题、发布机构、日期、链接及访问日期，数据库指标与查询口径。计算记录输入、来源、期间、币种、单位、公式及调整原因。

对转引数据追溯最初发布者。没有取得原始文件时同时保留实际读到的载体及其位置，标明“转引、原始发布未直接核验”，不把来源名称当作已完成核验。Wiki 引用记录页面标题、路径、具体章节、使用日期和实际证据身份。

冲突并列记录差异、来源日期、当前采用口径、可能原因和待核实动作。股权章节按报告指南采用公司提供的完整比例图表，工商差异保留，不推定工商变更已完成。

报告正文关键数字和事实使用 `[^1]` 数字脚注，从 1 起连续编号；同一数据再次出现复用脚注，邻近且同源数据可合并。正文行内不写材料编号。末尾的“资料来源附注（脚注表）”记录主张、材料编号、位置、证据身份和最初来源，并添加对应的 Markdown 脚注定义，使脚注可跳转。

正式项目沿用已有材料编号，外部来源可登记为外部引用；其他工作区可用本报告内的来源序号，不编造 PE 材料编号。过程稿使用来源键或临时编号，主 Agent 合稿时统一重排脚注，检查重复和缺号。

## 3. YAML 与链接

PE 工作台生成的报告和底稿使用以下公共 YAML 键：`title`、`document_type`、`project_id`、`project_name`、`stage`、`status`、`version`、`evidence_cutoff`、`owner`、`reviewer`、`last_updated`、`canonical`、`tags`、`aliases`、`related`。报告增加 `report_type: 初筛报告`；底稿增加 `workpaper_category`。未知字段留空，日期用 `YYYY-MM-DD`，状态用中文。

报告示例：

```yaml
---
title: "项目简称｜初筛报告"
document_type: report
project_id: PE-YYYY-NNN
project_name: 项目简称
stage: 10_机会录入与初筛
status: 待复核
version: v0.1
evidence_cutoff: YYYY-MM-DD
owner:
reviewer:
last_updated: YYYY-MM-DD
canonical: true
tags: [pe/project, pe/report]
aliases: []
related: []
report_type: 初筛报告
---
```

实际报告替换示例字段；过程稿使用同一组公共键，`document_type: report_draft`、`canonical: false`，状态采用“编制中／待复核／已复核”，不将临时章节另设为主底稿。报告和分析底稿为 `canonical: true`，两者通过汇聚关系衔接。

PE 工作台内部 Markdown 链接用从 Vault 根开始的完整 Wikilink，不带 `.md`，例如 `[[10_项目库/PE-YYYY-NNN_项目简称/00_项目控制/02_资料与证据|资料与证据]]`；替换为实际项目路径。其他工作区使用其原有约定，没有约定则普通相对 Markdown 链接和报告信息表即可。Skill 包本身采用相对 Markdown 资源链接及专用 Skill 元数据，不套项目 YAML。

## 4. 版本、审核与清理

- 初筛报告形成 `v0.x` 工作稿，交付状态为待复核；修改已冻结报告另起版本，不覆盖冻结文件。证据截止日取本次实际采用的截止日。
- “重点推进／研究推进／保持跟踪”是初筛分析建议。进入立项、启动全面尽调、投决和投后等阶段，以用户明确授权或正式记录为依据；不在本报告任务中自动启用。
- 用户审核通过本次报告后，登记对应版本并按 [DOCX 导出](DOCX导出.md) 同步生成 Word 版。过程稿清理与导出分别办理，先核对来源和计算已留存，再按授权清理对应批次。冻结 `v1.0` 须有明确批准。
- 删除前解析绝对路径，确认只在当前报告批次内；清除过程稿后检查报告与底稿没有指向被删文件的唯一来源链接。唯一证据或计算记录先迁入长期主维护位置。
- Markdown 是报告内容主版本。初筛 DOCX 由复核通过或用户明确要求触发，按专用规范省略脚注与来源附注；PDF、HTML 按用户要求导出并保留完整溯源。Word 审阅反馈采纳后回写 Markdown，涉及事实或判断时先改底稿。
- 本工作区报告导出件放在实际报告目录的 `90_按需导出/YYYYMMDD-HHMM/`；其他工作区沿当地约定。不因初筛写作自动发送、发布或上传敏感材料。

## 5. 模板维护

报告正文结构唯一维护在包内 [初筛报告模板](../assets/初筛报告模板.md)。本工作区的报告母版及轻量项目骨架中的初筛报告模板，是该正文加项目模板 YAML 的适配件；维护本 Skill 时同步两处适配正文。运行本 Skill 直接使用包内模板，不要求加载适配件。

方法归属：根据用户确认的 PE 工作台目录、来源、版本和授权规则内化。项目当期状态以实际记录为输入，不在本包预存任何项目结论。
